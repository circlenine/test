# 記録用スプシ 追加スクリプト

既存の統合スクリプト（Code.gs / v232）に足す形の追加ファイル群。
どれも Code.gs を差し替えるものではなく、**同じプロジェクトに別ファイルとして置く**。
`ALL_TABS` / `normalizePlace_` などは統合スクリプト側のものを使うので、重複定義はしていない。

| ファイル | 役割 | 状態 |
|---|---|---|
| `MapLink.gs` | G列の乗り場名 → Googleマップへのリンク | 実装済み |
| `ChartFit.gs` | まとめスプシのグラフをZ列の幅にそろえる | 実装済み |
| `Report.gs` | 自社実績／大物マップの2セクション集計 | **保留**（下記参照） |

# MapLink.gs — G列からGoogleマップへ

G列（乗り場）をタップするとGoogleマップが開くようにする。見た目（文字サイズ・色・太字）は変えない。

## なぜリッチテキストなのか

`=HYPERLINK()` の数式では**消える**。`formatTab_` が毎回 `setValues` でG列を書き戻すため。
そこでリッチテキストのリンクとして貼り、整形の最後に貼り直す方式にしている。

## 導入

1. Apps Script に `MapLink.gs` を新規ファイルとして追加
2. **統合スクリプトの `formatTab_` に1行足す**（これで貼りっぱなしになる）:

```js
  applyStyles_(sheet, out, meta);
  applyMapLinks_(sheet);        // ← この行を追加
```

3. メニューに出す場合は `onOpen()` の `m4` に:

```js
    .addItem("🗺 乗り場にマップリンクを貼る", "menuMapLinksApply")
    .addItem("🗺 マップの行き先を確認する", "menuMapLinksCheck")
```

2 を足さない場合は、整形のたびにリンクが消えるのでメニューから貼り直しが必要。

## 行き先の決まり方

`MAP_PLACES`（`normalizePlace_` を通した名前がキー）を引き、無ければ `"大阪市 " + 乗り場名` で検索する。

| 値の形 | 意味 |
|---|---|
| `{ q: "検索語" }` | その語でマップ検索 |
| `{ lat: 34.69, lng: 135.50 }` | 座標で一発表示（**こちらが正確**） |
| `{ q: "...", check: true }` | 場所が未確定。⚠️印が付く |

**新地1〜17・ガチマネプラ・ドン2 などの業界用語は場所が確定していません。**
メニュー「🗺 マップの行き先を確認する」で ⚠️ 付きの一覧が出るので、
違うものを教えてもらえれば座標に置き換えます（Googleマップで長押し → 座標をコピー でOK）。

折り返しの改行はスペースに戻してから検索する。消すと「セントレジス西向き」のように
語がくっついて検索が外れるため。

# Report.gs（保留）

**まとめスプシ側に、これより作り込まれたレポート（LINE Flex Message／曜日別・時間帯別）が
既に存在することが後から分かったため、このファイル単体での運用は保留。**
下記のうち、まとめスプシ側のレポートに取り込む価値があるのは次の2点:

- **オプチャ（A列空白）を自社実績の平均から除外する** ロジック
- **エリアタブ・関空・ﾊﾞﾗｼの写しを重複除外する** ロジック（993行 → 592行）

以下は保留中の仕様。

## セクション構成

| セクション | 内容 | 母集団 |
|---|---|---|
| 【自社実績】 | 平均売上・中央値・最高額・大物率（全体＋メンバー別） | **A列が「ｵﾌﾟﾁｬ」または空白の行を除外** |
| 【大物マップ】 | 乗り場ごとの金額帯別 件数分布 | **オプチャ行・空白行を含む全件** |

母集団が違うので、同じ表に混ぜず別セクションで出す。
オプチャは他人の目撃情報なので、自分たちの平均売上に混ぜると実績が歪む。
一方「どこで大物が出ているか」は他人の情報も含めて見たいので、そちらは全件が対象。

### A列の判定

**A列が空白の行はオプチャ扱い**（＝自社実績から除外・大物マップには計上）。

2026/09/01 時点の実データを確認したところ、**A列が「ｵﾌﾟﾁｬ」の行は0件**で、
オプチャ由来は **全て A列が空白のまま** 入っていた（993行中184行）。
「ｵﾌﾟﾁｬ」表記も念のため拾う（半角カナ `ｵﾌﾟﾁｬ` は全角に直してから判定）。

### 重複の除外

エリアタブ・関空・ﾊﾞﾗｼ は個人タブの写しなので、そのまま数えると二重・三重になる。
J列は写し側だけ埋まることがあり当てにならないため、
**内容（A列・営業日・E列・F列・G列）で重複を判定**する。
実データでは 993行 → 592行（重複401行）だった。

### 金額帯

記録用スプシのF列のセル色と同じ区切り。「大物」= ¥10,000以上。

| 帯 | 色 |
|---|---|
| 特大 ¥20,000〜 | ピンク `#ffbbd9` |
| 大物 ¥10,000〜 | 金 `#ffe086` |
| 中 ¥5,000〜 | 水色 `#c6f6ff` |
| 小 〜¥5,000 | 白 |

乗り場名は既存の `normalizePlace_` でまとめ、`REPORT_MERGE_RULES`（江坂／天満モスバーガー前／ドン2〇〇）は
**その名前が1件しかないときだけ**寄せる。何度も使われている正式な乗り場名は動かさない。

## 導入手順

1. スプレッドシート →「拡張機能」→「Apps Script」
2. 左の「ファイル」＋ →「スクリプト」→ 名前を `Report` にする
3. `Report.gs` の中身を丸ごと貼り付けて保存

`ALL_TABS` や `normalizePlace_` は統合スクリプト（Code.gs）側のものを使うため、
このファイルに重複定義は置いていない。**必ず同じプロジェクト内に置くこと。**

### メニューに出す（任意）

統合スクリプトの `onOpen()` の中、`m4`（⬆️ 整える・取り込む）に1行足す:

```js
  const m4 = ui.createMenu("⬆️ 整える・取り込む")
    .addItem("📜 過去分をまとめて取り込む", "menuHistoryImport")
    .addItem("🏷 乗り場名の表記ゆれを統一する", "menuPlaceUnify")
    .addItem("📥 オープンチャットの文章を取り込む", "menuPasteImport")
    .addItem("📊 売上レポートを作る", "menuSalesReport")   // ← この行を追加
    .addItem("🔗 個人タブの内容を他タブへ反映する", "menuRebuild");
```

足さなくても、スクリプトエディタで `buildSalesReport` を選んで実行すれば動く。

## 出力先

「レポート」タブ（毎回クリアして作り直す）。
`ALL_TABS` に含まれないので `formatTab_` / `rebuildDerivedTabs` / `onEdit` の対象外。
**記録用のタブは一切変更しない。**

## テスト

```
node gas/test/maplink.test.js
node gas/test/chartfit.test.js
node gas/test/report.test.js
```

`gas/test/gas-globals.js` は統合スクリプトから必要な部分だけ抜き出した写し（テスト専用）。
