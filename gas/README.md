# 記録用スプシ 追加スクリプト

既存の統合スクリプト（Code.gs / v232）に足す形の追加ファイル群。
どれも Code.gs を差し替えるものではなく、**同じプロジェクトに別ファイルとして置く**。
`ALL_TABS` / `normalizePlace_` などは統合スクリプト側のものを使うので、重複定義はしていない。

| ファイル | 役割 | 状態 |
|---|---|---|
| `MapLink.gs` | G列の乗り場名 → Googleマップへのリンク | 実装済み |
| `ChartFit.gs` | まとめスプシのグラフをZ列の幅にそろえる | 実装済み |
| `LineReport.gs` | LINE画像(Flex)＋まとめスプシのレポート作成 | **v185からの抜粋** |
| `BigMap.gs` | オプチャ込みの大物マップ | 実装済み |

---

# MapLink.gs — G列からGoogleマップへ

G列（乗り場）をタップするとGoogleマップが開くようにする。見た目（文字サイズ・色・太字）は変えない。

## なぜリッチテキストなのか

`=HYPERLINK()` の数式では**消える**。`formatTab_` が毎回 `setValues` でG列を書き戻すため。
そこでリッチテキストのリンクとして貼り、整形の最後に貼り直す方式にしている。

## 導入

1. Apps Script に `MapLink.gs` を新規ファイルとして追加
2. **統合スクリプトの `formatTab_` に1行足す**（これで貼りっぱなしになる）:

```js
  applyStyles_(sheet, out, meta);
  applyMapLinks_(sheet);        // ← この行を追加
```

3. メニューに出す場合は `onOpen()` の `m4` に:

```js
    .addItem("🗺 乗り場にマップリンクを貼る", "menuMapLinksApply")
    .addItem("🗺 マップの行き先を確認する", "menuMapLinksCheck")
```

2 を足さない場合は、整形のたびにリンクが消えるのでメニューから貼り直しが必要。

## 行き先の決まり方

`MAP_PLACES`（`normalizePlace_` を通した名前がキー）を引き、無ければ `"大阪市 " + 乗り場名` で検索する。

| 値の形 | 意味 |
|---|---|
| `{ q: "検索語" }` | その語でマップ検索 |
| `{ lat: 34.69, lng: 135.50 }` | 座標で一発表示（**こちらが正確**） |
| `{ q: "...", check: true }` | 場所が未確定。⚠️印が付く |

**新地1〜17・ガチマネプラ・ドン2 などの業界用語は場所が確定していません。**
メニュー「🗺 マップの行き先を確認する」で ⚠️ 付きの一覧が出るので、
違うものを教えてもらえれば座標に置き換えます（Googleマップで長押し → 座標をコピー でOK）。

折り返しの改行はスペースに戻してから検索する。消すと「セントレジス西向き」のように
語がくっついて検索が外れるため。

# BigMap.gs — オプチャ込みの大物マップ

「どこで大物（￥10,000以上）が出ているか」を、オプチャ情報も含めて出す。

## 自社 / オプチャ の見分け方（ここが肝）

**A列が空白かどうかでは判定しない。** 実データを調べた結果:

| A列空白 184件の内訳 | 件数 | 正体 |
|---|---|---|
| 個人タブに同じ乗車がある | 50件 (27%) | **自社の記録の写し**。A列だけ失われている |
| 個人タブに同じ乗車が無い | 134件 (73%) | エリアタブにしか無い＝外から来た情報 |

「A列空白＝オプチャ」とすると、**自分たちの実績を4件に1件の割合で捨てる**。

そこで **「個人タブに同じ乗車（営業日＋乗車時間＋金額）があるか」** で判定する。
A列が空でも名前入りでも正しく分かれる。

なお `importPastedText` はA列に `ｵﾌﾟﾁｬ` を入れる実装なのに、実データに `ｵﾌﾟﾁｬ` は
**0件**だった。空白行は貼り付け取込とは別の経路で入っている。

## 出す内容

1. **大物マップ** — 乗り場ごとに 大物件数 / うち自社 / うちオプチャ / 全件数 / 最高額
2. **🎯 オプチャだけが知っている大物** — 自社の大物0件・オプチャには大物あり。
   ＝ まだ自分たちが取れていない場所。オプチャ情報を集めている意味そのもの。

件数が1件のものは「平均￥X」ではなく「1件 ￥X」と書く（実績があるように見せないため）。

## 使い方

3通りの入口がある。

| 関数 | 用途 |
|---|---|
| `menuBigMap` | **メニューから単体で確認**（スプシもLINEも変更しない） |
| `bmFlexBlock_(bm)` | LINE画像に差し込む Flex の配列を返す |
| `bmWriteSection_(sheet, row, bm)` | まとめスプシにセクションを書く |

レポート側への組み込み:

```js
const bm = buildBigMap(startD, endD);
bmFlexBlock_(bm).forEach(function (c) { flexContents.push(c); });  // LINE画像
curRow = bmWriteSection_(sheet, curRow, bm);                        // まとめスプシ
```

`onOpen()` の `m4` に足す場合:

```js
    .addItem("🗺️ 大物マップを見る", "menuBigMap")
```

## 依存（統合スクリプト側にある必要があるもの）

`PERSONAL_TABS` / `ALL_TABS` / `START_ROW` / `LAST_COL` / `C_*` /
`normalizePlace_` / `ymdOf_` / `fmtDate_` / `getGridRange`（スプシ出力時のみ） /
`runnerDialog_` / `progressWidget_` / `progSet_` / `progClear_`

`getGridRange` は LineReport.gs 側にある。`toHalfWidthKana` は無くても動く。
