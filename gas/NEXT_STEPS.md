## みんなの記録ページ（004-WebApp.gs / W001ver）

スプレッドシートは「データの置き場所」、見るのはこのページ、という分け方。

### 公開のしかた（初回だけ）

1. Apps Script に `004-WebApp` として貼る
2. 右上「デプロイ」→「新しいデプロイ」
3. 種類：**ウェブアプリ**
4. 次のユーザーとして実行：**自分**
5. アクセスできるユーザー：**全員**
6. 出てきたURLをLINEグループに貼る

### 鍵のかけ方（W002ver から）

「設定」タブの2項目で決める。どちらも空なら、URLを知っている人は誰でも見られる。

| 項目 | 効果 | 向いている場面 |
|---|---|---|
| ページの合言葉 | 合言葉を知っている人だけ | **おすすめ。** Googleログイン不要、LINEの中のブラウザでそのまま開ける |
| ページを見られるメール | 書いたGoogleアカウントだけ | いちばん固い。ただし下の設定変更と、各自のGoogleログインが要る |

**メールで制限する場合だけ**、デプロイの設定を変える必要がある。

1. デプロイを管理 → 鉛筆マーク
2. 実行するユーザー：**ウェブアプリにアクセスしているユーザー**
3. アクセスできるユーザー：**Googleアカウントを持つ全員**
4. 記録用スプシを、その人たちに**閲覧者**として共有しておく
   （スクリプトがその人の権限で動くため）

この設定にしていないと相手のメールが取れないので、ページは
「設定が足りません」と出る。合言葉も一緒に入れておけば、そちらに切り替わる。

鍵がかかっているあいだは、記録は1件もページに渡していない
（ページのソースを見ても中身は出てこない）。

### 直したとき（毎回これが要る）

```
デプロイ → デプロイを管理 → 鉛筆マーク → バージョン「新バージョン」→ デプロイ
```

**ファイルを足したり直したりしただけでは、公開中のページには反映されない。**
デプロイは「そのときのコードの写し」を配っているため。
URLは変わらない。

### よくあるエラー

| 出るもの | 原因 | 直し方 |
|---|---|---|
| 現在、ファイルを開くことができません | 公開中のバージョンに `doGet` が無い（004-WebApp を貼る前にデプロイした） | 上の「新バージョン」でデプロイし直す |
| ログインを求められる | アクセスできるユーザーが「自分のみ」 | 「全員」に変える |
| 承認画面が出る | 実行するユーザーが「アクセスしているユーザー」 | メール制限を使わないなら「自分」に戻す |

### 直すとき
`gas/parts/WebApp.gs`（集める側）と `gas/parts/webapp.html`（画面）を直して
`python3 tools/build_webapp.py`。

### まだやっていないこと
- LINEのリッチメニューにボタンを置いて1タップで開けるようにする
- レポートの赤いボタンの行き先を、スプシからこのページに変える
- 待ち時間あたりの効率（￥/h）を立ち回りタブに出す
- 読み込みが遅いと感じたら、静的サイト方式（GitHub Pages）へ移す

## コードの自動更新（005-Updater.gs / U001ver）

貼り替えをなくす仕組み。メニューのボタン1つで、
GitHub（またはGoogleドライブ）から新しいコードを読んで、自分自身を書き換える。
ウェブアプリのデプロイもやり直すので、ページも同時に最新になる。

### 最初の1回だけ（ここだけ手作業）

1. ブラウザで `script.google.com/home/usersettings` を開き、
   **「Google Apps Script API」を ON**
2. Apps Script に `005-Updater` を新規ファイルとして追加し、貼る
3. `001-Code` を貼り替える（メニューを出すため）
4. `appsscript.json` を貼り替える
   ⚙️ プロジェクトの設定 →「appsscript.json マニフェスト ファイルをエディタで表示する」を ON
5. メニュー「🅰️ はじめの設定 →🔄 コードの更新 →🔑 GitHubの鍵を設定」
   - リポジトリ名：`circlenine/test`
   - ブランチ：`claude/gas-code-info-collection-e5mxw3`
   - フォルダ：`gas`
   - トークン：GitHubで作った読み取り専用のもの
6. 「🔄 コードを更新する」を1回押して、承認画面を通す

### GitHubトークンの作り方（スマホでも可）

```
github.com → 右上のアイコン → Settings
→ Developer settings → Personal access tokens → Fine-grained tokens
→ Generate new token
　　Repository access : Only select repositories → circlenine/test
　　Permissions       : Repository permissions → Contents → Read-only
→ Generate token → 表示された github_pat_… をコピー
```

読み取り専用・そのリポジトリだけ、にすること。
トークンは ScriptProperties にしまわれる。コードにもシートにも書かれない。

### 以降

私が GitHub に push する → 「🔄 コードを更新する」を押す → 終わり。

### 壊れたときは

- メニュー「⏪ 前のコードに戻す」で、書き換える直前に戻せる
- ドライブの `taxi-gas/backup/日時/` に全ファイルが残っている（10世代）
- それも無理なら、GitHub から手で貼り直す

### 注意

- `script.projects` は、他のApps Scriptプロジェクトも編集できる広い権限。
- 書き換えは必ずバックアップを取ってから。取れなければ書き込まない。
- `appsscript` が含まれない書き込みは、危ないので拒否する。
