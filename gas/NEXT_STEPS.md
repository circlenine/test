## みんなの記録ページ（004-WebApp.gs / W001ver）

スプレッドシートは「データの置き場所」、見るのはこのページ、という分け方。

### 公開のしかた（初回だけ）

1. Apps Script に `004-WebApp` として貼る
2. 右上「デプロイ」→「新しいデプロイ」
3. 種類：**ウェブアプリ**
4. 次のユーザーとして実行：**自分**
5. アクセスできるユーザー：**全員**
6. 出てきたURLをLINEグループに貼る

### 鍵のかけ方（W002ver から）

「設定」タブの2項目で決める。どちらも空なら、URLを知っている人は誰でも見られる。

| 項目 | 効果 | 向いている場面 |
|---|---|---|
| ページの合言葉 | 合言葉を知っている人だけ | **おすすめ。** Googleログイン不要、LINEの中のブラウザでそのまま開ける |
| ページを見られるメール | 書いたGoogleアカウントだけ | いちばん固い。ただし下の設定変更と、各自のGoogleログインが要る |

**メールで制限する場合だけ**、デプロイの設定を変える必要がある。

1. デプロイを管理 → 鉛筆マーク
2. 実行するユーザー：**ウェブアプリにアクセスしているユーザー**
3. アクセスできるユーザー：**Googleアカウントを持つ全員**
4. 記録用スプシを、その人たちに**閲覧者**として共有しておく
   （スクリプトがその人の権限で動くため）

この設定にしていないと相手のメールが取れないので、ページは
「設定が足りません」と出る。合言葉も一緒に入れておけば、そちらに切り替わる。

鍵がかかっているあいだは、記録は1件もページに渡していない
（ページのソースを見ても中身は出てこない）。

### 直したとき（毎回これが要る）

```
デプロイ → デプロイを管理 → 鉛筆マーク → バージョン「新バージョン」→ デプロイ
```

**ファイルを足したり直したりしただけでは、公開中のページには反映されない。**
デプロイは「そのときのコードの写し」を配っているため。
URLは変わらない。

### よくあるエラー

| 出るもの | 原因 | 直し方 |
|---|---|---|
| 現在、ファイルを開くことができません | 公開中のバージョンに `doGet` が無い（004-WebApp を貼る前にデプロイした） | 上の「新バージョン」でデプロイし直す |
| ログインを求められる | アクセスできるユーザーが「自分のみ」 | 「全員」に変える |
| 承認画面が出る | 実行するユーザーが「アクセスしているユーザー」 | メール制限を使わないなら「自分」に戻す |

### 直すとき
`gas/parts/WebApp.gs`（集める側）と `gas/parts/webapp.html`（画面）を直して
`python3 tools/build_webapp.py`。

### まだやっていないこと
- LINEのリッチメニューにボタンを置いて1タップで開けるようにする
- レポートの赤いボタンの行き先を、スプシからこのページに変える
- 待ち時間あたりの効率（￥/h）を立ち回りタブに出す
- 読み込みが遅いと感じたら、静的サイト方式（GitHub Pages）へ移す

## コードの自動更新（005-Updater.gs / U001ver）

貼り替えをなくす仕組み。メニューのボタン1つで、
GitHub（またはGoogleドライブ）から新しいコードを読んで、自分自身を書き換える。
ウェブアプリのデプロイもやり直すので、ページも同時に最新になる。

### 最初の1回だけ（ここだけ手作業）

1. ブラウザで `script.google.com/home/usersettings` を開き、
   **「Google Apps Script API」を ON**
2. Apps Script に `005-Updater` を新規ファイルとして追加し、貼る
3. `001-Code` を貼り替える（メニューを出すため）
4. `appsscript.json` を貼り替える
   ⚙️ プロジェクトの設定 →「appsscript.json マニフェスト ファイルをエディタで表示する」を ON
5. メニュー「🅰️ はじめの設定 →🔄 コードの更新 →🔑 GitHubの鍵を設定」
   - リポジトリ名：`circlenine/test`
   - ブランチ：`claude/gas-code-info-collection-e5mxw3`
   - フォルダ：`gas`
   - トークン：GitHubで作った読み取り専用のもの
6. 「🔄 コードを更新する」を1回押して、承認画面を通す

### GitHubトークンの作り方（スマホでも可）

```
github.com → 右上のアイコン → Settings
→ Developer settings → Personal access tokens → Fine-grained tokens
→ Generate new token
　　Repository access : Only select repositories → circlenine/test
　　Permissions       : Repository permissions → Contents → Read-only
→ Generate token → 表示された github_pat_… をコピー
```

読み取り専用・そのリポジトリだけ、にすること。
トークンは ScriptProperties にしまわれる。コードにもシートにも書かれない。

### スマホアプリから動かす（「そうさ」タブ）

Googleスプレッドシートの**アプリ版ではカスタムメニューが出ない**。
ボタン（図形）にスクリプトを割り当てても、アプリからは押せない。
できるのは「セルにチェックを入れる」ことだけ。

そこで「説明」タブの**8行目から下**にチェックを置き、そこで動かす。
新しいタブは作らない。

```
🅰️ はじめの設定 → 🔄 コードの更新 → 🧰 そうさボタンを置く（説明タブ・スマホアプリ用）
```

| 場所 | 中身 |
|---|---|
| 見出しの行 | `▼ チェックを入れると動きます…` |
| その次の行〜 | チェック（B列・文字サイズ50）／ラベル／説明 |
| さらに下 | 結果 |
| Z1・Z2 | グループID・ダッシュボードID（今までどおり） |
| Y3〜Z5 | ページURL・診断結果・更新結果 |

**はじめて置くときは、行そのものを差し込む。**
既にある行に書き込むのではなく `insertRowsBefore` で新しい行を作ってから書く。
だから、もともと入っているものを消してしまうことがない。

**チェックは B列。A列は余白として使っているため。**
文字サイズ50・行の高さ70で置くので、スマホの指でも押しやすい。
ラベルはそのすぐ右、説明はそのまた右。

**列も決め打ちにしていない。**
見出しの次の行で、いちばん左にある true/false のセルを「チェックの列」とみなす。
だから A列に置いていても B列に置いていても、そのまま動く。
結果はチェックのすぐ右の列に出る。

**行の位置は決め打ちにしていない。**
はじめて置くときだけ8行目を使い、そのあとは
B列の「チェックを入れると動きます」という文字を `createTextFinder` で探す。

説明タブは、3行目に新しい更新情報を足していく運用なので、
その下の行は**必ずずれる**。だから位置を覚えない作りにしてある。
何行足しても、どこへ動かしても、セルを結合しても、そのまま動く。
（見つけた行は覚えておくが、毎回そこが見出しかを確かめ、違えば探し直す）

**どのボタンかは「書いてある文言」で決める。行の順番では決めない。**
順番で決めると、途中に足したり並べ替えたりしたときに
「書いてある名前」と「動くもの」がずれる。実際に一度そうなった。
文言に下の言葉が含まれていれば、そのボタンとみなす。

| 番号 | 見分ける言葉 | 動くもの |
|---|---|---|
| [1] | コードを更新 | GitHubから取り込んでデプロイ |
| [2] | 更新できる状態 | 状態を調べる |
| [3] | 全タブをまとめて整形 | 整形 |
| [4] | 前のコードに戻す | 巻き戻し |
| [5] | URLをLINE | URLをグループLINEへ |
| [6] | 開けるか調べる | ページが開けるか試す |

やりとりでは番号で呼ぶ（「[3]を押してください」）。
先頭が絵文字だと言葉で説明しづらく、取り違えやすいため。

だから、絵文字を変えても、前後に文字を足しても、並べ替えても、見たとおりに動く。
言葉で分からないときは、先頭の `[1]`〜`[6]` の番号で見分ける
（`（5）` や `6.` の書き方も読む）。文言と番号が食い違ったら、文言のほうを信じる。
分からない文言の行を押すと「何をするボタンか分かりません」と出て、
正しい文言の一覧を見せる（実行はしない）。

**ボタンの間に空の行を入れてよい。**
押し間違いが怖いので1行おきに空けている。
チェックのある行だけを拾い、空行は飛ばす。
「結果」と書いてある行まで来たら、そこがボタンの終わり。
空行が4行続いたときも、そこで終わりとみなす。
空行を押しても（チェックが無いので）何も起きない。

**結果らんも探す。**
最後のボタンの下から「結果」と書いてある行を探し、そのすぐ下の同じ列に書く。
だから結果をB列に動かしても、そのまま付いていく。

**ボタンはいつも6つ並べる。**
入れていないファイルの機能も並べる。数が変わると、
結果らんの行も保護する範囲もずれてしまうため。
入れていない機能を押すと「まだ使えません（004-WebApp を入れてください）」と出る。

**足りないボタンは足す。重複していたら、こちらでは直さない。**
すでに置いてあるボタンの文言・書式・結合は書き換えない。
足りないものだけを、最後のボタンのすぐ下に足す（上の行の書式を引き継ぐ）。
同じものが2つある／文言が読めない行があるときは、セルを一切さわらず、
「何行目が重複しているか」「何が足りないか」「どう直すか」を知らせるだけにする。
見た目を整えてもらっているので、勝手に並べ直すほうが困るため。

**2回目からは並べ直さない。**
すでに置いてあるときは、ラベルも見出しも書き換えない
（自分で整えた見た目を壊さないため）。入れ直すのは見張りと保護だけ。

チェックを入れると動き、終わると自動でチェックが外れ、「結果」らんに出る。

**既にあるものは絶対に消さない。**
`clear()` は使わず、8行目から下の A〜C 列だけを書く。
そこに見覚えのないものが入っていたら、**何も書かずに中止**して
「何行目に何があったか」を知らせる。

動かす仕組みは2つ入れてある。
- `panelOnEdit`（onEditトリガー）… チェックした瞬間に動く
- `panelWatch`（1分おき）        … onEditが効かない機種のための保険

どちらか片方でも効けば動く。二重に動かないよう LockService で鍵をかけてある。
1分おきの実行が気になるなら「⏸ 1分おきの見張りを止める」で止められる
（その場合、アプリからは動かなくなる可能性がある）。

### 誰が押せるか

チェックのらん（A列のボタン部分だけ）は、置いた時点で
**自分だけが編集できるよう自動で保護**される。
「説明」タブ全体ではないので、他の行は今までどおりみんなが読み書きできる。
ここのチェックはコードの更新や巻き戻しを走らせるスイッチなので、
編集権限のある人なら誰でも押せる状態にはしない。

- ほかの編集者にはタブは**見える**が、チェックは**入れられない**
- スクリプトは所有者として動くので、保護があっても書き込める
- 誰かに使わせたいときは「データ → シートと範囲を保護」でその人を足す
- 保護をかけられなかったときは、はっきりそう出す（黙って無防備にしない）

注意:
- 保護が効くのは**編集権限を持っている人**に対してだけ。閲覧者は元々編集できない。
- 「警告を表示する」を選ぶと**止められない**。「編集できるユーザーを制限する」のほう。
- タブを隠すのは目隠しであって、保護ではない（誰でも再表示できる）。

### 「[1] コードを更新する」が実際にやること

1. GitHub から新しいコードを読む
2. いまのコードをドライブに全部保存する（保存できなければ、ここで中止）
3. Apps Script API でプロジェクトの中身を書き換える
4. **新しい版を作り、いまあるデプロイを全部その版に切り替える**

4 が大事。デプロイは「そのときのコードの写し」なので、
ここをやらないと、コードを直しても動いているものは古いまま。

**URLは変わらない。** 既にあるデプロイの版を上げるだけで、
新しいデプロイは作らない。だから:

- LINEの Webhook URL … **差し替え不要**（同じURLのまま中身が新しくなる）
- みんなの記録ページのURL … **変わらない**

LINEの受け口も、みんなの記録ページも、同じスクリプトの別デプロイなので、
どちらも同時に新しい版になる。

「[4] 前のコードに戻す」も同じく、戻したあとデプロイをやり直す
（U004ver で追加。それまではコードだけ戻して、動いているものは古いままだった）。

### やらないこと

- LINE Developers 側の Webhook URL の登録そのもの（触らない。触る必要がない）
- 新しいデプロイの作成（作るとURLが変わり、LINEの受け口が切れるため）
- デプロイの削除

### 以降

私が GitHub に push する → 「そうさ」タブで [1] にチェック → 終わり。

### 壊れたときは

- メニュー「⏪ 前のコードに戻す」で、書き換える直前に戻せる

- 書き換えは必ずバックアップを取ってから。取れなければ書き込まない。
- `appsscript` が含まれない書き込みは、危ないので拒否する。
