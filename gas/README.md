# 記録用スプシ 追加スクリプト

## バージョンの付け方

ファイルの先頭に記号＋3桁の番号を書く。直したら数字を1つ増やし、履歴に何を直したか書く。

| 記号 | ファイル | いま | Apps Script 側の名前 |
|---|---|---|---|
| **C** | `001-Code.gs`（統合スクリプト） | C019ver | `001-Code` |
| **E** | `002-Extras.gs` | E004ver | `002-Extras` |
| **L** | `003-LineReport.gs` | L005ver | `003-LineReport` |
| **W** | `004-WebApp.gs`（みんなの記録ページ） | W003ver | `004-WebApp` |

**貼るのはこの4つだけ。** 番号の順に並ぶので、上から順に貼っていけば漏れない。
`gas/parts/` の中は、`002-Extras.gs` を組み立てるための材料なので貼らなくてよい。

Apps Script 上のファイル名も **`001-Code`** のようにそろえる（旧: `コード` / `Code`）。
名前の変更は、ファイル一覧でそのファイルの **⋮** → 「名前を変更」から。

いま動いているバージョンは、メニュー「**ℹ️ バージョンを確認**」で見られる。
手元のファイルと実際に動いているものがずれていないか、これで確かめられる。

`002-Extras.gs` は `tools/build_extras.py` で組み立てる（バージョンと履歴もそこで管理）。
`004-WebApp.gs` は `tools/build_webapp.py` で組み立てる。
直すのは `gas/parts/WebApp.gs`（データを集める側）と
`gas/parts/webapp.html`（画面）のほう。
`gas/parts/Strategy.gs` / `Opucha.gs` / `ChartFit.gs` を直したら:

```
python3 tools/build_extras.py
```

同じ名前の宣言が2つあると Apps Script はプロジェクト全体を止めるので、
組み立て時に必ず重複を調べ、見つかったら中断する。

既存の統合スクリプト（001-Code.gs）に足す形の追加ファイル群。
どれも 001-Code.gs を差し替えるものではなく、**同じプロジェクトに別ファイルとして置く**。
`ALL_TABS` / `normalizePlace_` などは統合スクリプト側のものを使うので、重複定義はしていない。

| ファイル | 役割 | 状態 |
|---|---|---|
| `parts/MapLink.gs` | G列の乗り場名 → Googleマップへのリンク | 実装済み |
| `parts/ChartFit.gs` | まとめスプシのグラフをZ列の幅にそろえる | 実装済み |
| `003-LineReport.gs` | LINE画像(Flex)＋まとめスプシのレポート作成 | **v185からの抜粋** |
| `002-Extras.gs` | 下の3つを1ファイルに束ねたもの（**貼るのはこれ1つでOK**） | 実装済み |
| `parts/Opucha.gs` | どれがオプチャかを検索して指定する画面 | 実装済み |
| `parts/Strategy.gs` | 立ち回り分析＋ロングマップ | 実装済み |

# MapLink.gs — G列からGoogleマップへ

G列（乗り場）をタップするとGoogleマップが開くようにする。見た目（文字サイズ・色・太字）は変えない。

## なぜリッチテキストなのか

`=HYPERLINK()` の数式では**消える**。`formatTab_` が毎回 `setValues` でG列を書き戻すため。
そこでリッチテキストのリンクとして貼り、整形の最後に貼り直す方式にしている。

## 導入

1. Apps Script に `gas/parts/MapLink.gs` を新規ファイルとして追加
2. **統合スクリプトの `formatTab_` に1行足す**（これで貼りっぱなしになる）:

```js
  applyStyles_(sheet, out, meta);
  applyMapLinks_(sheet);        // ← この行を追加
```

3. メニューに出す場合は `onOpen()` の `m4` に:

```js
    .addItem("🗺 乗り場にマップリンクを貼る", "menuMapLinksApply")
    .addItem("🗺 マップの行き先を確認する", "menuMapLinksCheck")
```

2 を足さない場合は、整形のたびにリンクが消えるのでメニューから貼り直しが必要。

## 行き先の決まり方

`MAP_PLACES`（`normalizePlace_` を通した名前がキー）を引き、無ければ `"大阪市 " + 乗り場名` で検索する。

| 値の形 | 意味 |
|---|---|
| `{ q: "検索語" }` | その語でマップ検索 |
| `{ lat: 34.69, lng: 135.50 }` | 座標で一発表示（**こちらが正確**） |
| `{ q: "...", check: true }` | 場所が未確定。⚠️印が付く |

**新地1〜17・ガチマネプラ・ドン2 などの業界用語は場所が確定していません。**
メニュー「🗺 マップの行き先を確認する」で ⚠️ 付きの一覧が出るので、
違うものを教えてもらえれば座標に置き換えます（Googleマップで長押し → 座標をコピー でOK）。

折り返しの改行はスペースに戻してから検索する。消すと「セントレジス西向き」のように
語がくっついて検索が外れるため。

# Opucha.gs — オプチャ印を付ける／外す

## なぜ手動指定なのか

オプチャ情報は、タブや列を見ても**機械的に判定できない**。

- LINE連携前の記録は A列が空のまま個人タブに入っている（これは自社実績）
- 過去にLINEのメッセージで送ったオプチャ情報も個人タブに入っている
- 関空タブにも自社の乗車が混ざっている

A列の空白でもタブでも判定できないので、**どれがオプチャかは人が決める**しかない。
そのための検索＋チェック画面。

## 印の持ち方

本体は**スクリプトプロパティ** `OPUCHA_MARKS`。

```
{ "2026-05-21|23:48|1300": "元のA列の値", ... }
```

整形（`formatTab_`）や連動タブの作り直しで消えないようにするため。
見た目としては **A列に `ｵﾌﾟﾁｬ` と表示**し、印を外すと**元の値に戻る**。

乗車キーに乗り場を含めないのは、表記ゆれで変わってしまうため。

## 使い方

メニュー →「🏷 オプチャ印を付ける／外す」

1. **検索**（乗り場・そのほか・日付・金額範囲・タブ・「今オプチャの行だけ」）
2. **チェックを付け外し**（チェック＝オプチャ。今オプチャの行は最初から付いている）
3. **反映**

**一覧に出ている行だけが反映される。** 検索でヒットしていない行は触らない。
同じ乗車が複数タブにあっても1件にまとめて表示し、反映は全タブに及ぶ。

検索は空白区切りでAND。1度に300件まで表示する。

## 今後

LINEの画像スクショから読み取ったものは自動でオプチャ扱いにする予定。
それ以外（過去分・手打ち分）はこの画面から指定する。

## メニューへの追加

```js
    .addItem("🏷 オプチャ印を付ける／外す", "menuOpucha")
```

# Strategy.gs — 立ち回り分析

「何曜日の、何時に、どの乗り場が良いか」を記録から出す。

## 金額の区分

| 区分 | 金額 |
|---|---|
| ショート | ￥4,999以下 |
| ミドル | ￥5,000〜￥9,999 |
| ロング | ￥10,000以上 |

## 自社 / オプチャ の見分け方

**`Opucha.gs` の印で判定する。** タブや列からは機械的に判定できないため。
`Opucha.gs` が入っていない場合は全件を自社として集計する（印0件のうちも同じ）。

## 出す内容

1. **立ち回り候補** — 曜日区分 × 時間帯 × 乗り場。3件以上ある枠のみ
2. **待ち時間あたりの効率** — 乗り場別。平均売上が高くても待ちが長ければ本数が減る
3. **曜日ごと** — 特定曜日の癖。一番ロング率の高い曜日は時間帯まで割って出す
4. **ロングマップ（オプチャ込み）** — 自社/オプチャの内訳つき

### 件数が少ない枠を過大評価しない

1件だけの￥25,000がいきなり1位に来ると立ち回りを誤るので、
**件数が少ない枠の平均は全体平均へ寄せて**並べる（`stShrink_`）。
件数が増えるほど実際の平均に近づく。表には実平均と補正後の両方を出す。

## 使い方

メニュー →「🎯 立ち回りを見る」。**スプシもLINEも変更しない。**

`onOpen()` の `m4` に足す場合:

```js
    .addItem("🎯 立ち回り分析", "menuStrategy")
```

## 依存（統合スクリプト側にある必要があるもの）

`PERSONAL_TABS` / `ALL_TABS` / `START_ROW` / `LAST_COL` / `C_*` / `HOLIDAYS` /
`isHoliday_` / `normalizePlace_` / `ymdOf_` / `fmtDate_` /
`runnerDialog_` / `progressWidget_` / `progSet_` / `progClear_`
